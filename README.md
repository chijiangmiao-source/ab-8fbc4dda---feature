# 超导磁通探针整数相位面复核

从带整周跳变的有向边差观测中，**精确**复原一张可用于补偿的整数相位面；
并可在既有相位面上勾选可疑边，规划一条回到出发点的**最短有向复测闭环**。
所有重计算在浏览器内的 Web Worker 中完成，页面本身是零运行时依赖的纯静态应用。

## 解决的问题

- 探针编号 `0 … n-1`（2 ≤ n ≤ 40），其中一个**参考探针固定相位为 0**；
- 每个探针有整数相位范围 `[lo_i, hi_i]`；
- 有向观测边 `u → v` 给出目标差值 `t_e` 与正整数权重 `w_e`；
- 在**所有**范围内整数赋值中最小化

      Σ_e w_e · | (x_v − x_u) − t_e |

- 总成本相同时，取按探针标识升序的相位向量 `(x_0, x_1, …)` **字典序最小**者。

不沿生成树逐边累加（闭环矛盾时局部传播不是最优），不使用浮点，也不枚举全赋值。

## 复测闭环规划

校准员在获得既有相位面后，可在观测边表中勾选**至多 24 条**需要重新测量的
可疑边并指定出发探针 `s`，一次巡检覆盖全部可疑边，而非分别安排往返：

- 只能沿当前录入的**有向**观测边前进，可疑边至少经过一次，其余边作过渡；
- 输出完整边序、每步起止探针、每条可疑边的**首次到达位置**与闭环长度；
- 某可疑边 `u→v` 无法纳入闭环时，明确指出**从何探针不能到达何处**
  （`s` 到不了 `u`，或经该边到 `v` 后回不到 `s`）并清除旧路线。

算法（[src/lib/routeplanner.js](src/lib/routeplanner.js)，三步均为整数精确计算，
不逐边贪心、不枚举路线、不用浮点费用）：

1. **有向最短过渡路**：每条边经过代价为 1，从每个探针做一次 BFS，
   得到全源最短路与前驱边（单向绕行被正确计入）；
2. **整数最小费用平衡**：按勾选边造成的入出度失衡 `d(v)=入−出` 建流网络——
   `d>0` 的探针需补出发路、`d<0` 的需补到达路，`a→b` 过渡弧费用为最短路
   跳数；逐次最短路增广（Bellman-Ford，残量负费用同样整数）求最小费用流。
   出发点与勾选边均不相邻时，用节点拆分强制一对“离开/回到 `s`”的流量，
   与失衡配平联合取最优；
3. **展开欧拉闭环**：勾选边 + 配平用的最短过渡路构成平衡有向多重图，
   残余平衡连通块用最便宜的成对往返路挂接后，从 `s` 做 Hierholzer
   得到一条欧拉闭环。

## 算法：凸整数标签 → 最小割（一次最大流）

有序整数标签的凸代价可归约为 s-t 最小割（Ishikawa 链式图）：

- 二值变量 `z_{i,k} = [x_i ≥ k]`，节点 `(i,k)` 在源侧 ⇔ `z=1`；
- 链内 `+∞` 弧 `(i,k+1) → (i,k)` 强制截集是一个阈值；
- 成对项 `w·|x_v − x_u − t|` 的受限二阶差分仅当 `l − k = t` 时为 `2w`，
  对应弧 `(u,k) → (v,l)`；有限定义域边界的一阶项用源/汇弧精确补偿；
- 参考探针用 `+∞` 钉死弧固定为 0；
- 整数容量 Dinic（显式栈迭代实现，宽范围不栈溢出）求最大流；
- 最大流后从源点沿残量弧可达的集合是**唯一的最小最小割**，
  它在所有最优割中逐分量最小，因而解码出的正是字典序最小的最优解——无需多轮求解。

总代价与每条边的实际差/残差/贡献在求解后按定义用整数复算，并与网络值交叉核对。

## 浏览器中的并发生命周期

- 最小割与闭环规划都运行在 [Web Worker](src/worker/solver.worker.js) 中，
  异步计算会周期性让出事件循环；
- 复核与规划各持一枚**代际令牌**；草稿修改、勾选变更、发起新任务或点击
  取消都会作废对应旧令牌，旧计算在下一个让出点停止且其结果永不回传，
  主线程也只接受当前代际的消息——旧计算/旧规划不可能覆盖当前界面状态；
- 仅修改复测勾选或出发探针时，只作废旧规划并清除旧路线，
  **不触碰当前复核结论**；
- 校验失败（范围为空、参考点 0 越界、边端点不存在、权重非正整数、
  勾选超 24 条、出发探针越界等）会在页面上定位到具体探针行/边字段/
  出发探针输入框，并清除旧结论与旧路线。

## Docker Compose

`compose.yaml` 提供两个服务：

```bash
# 页面（静态应用），宿主机端口默认 8080，可用 WEB_PORT 覆盖：
docker compose up web
#   浏览器打开 http://localhost:8080
WEB_PORT=9000 docker compose up web

# 一次性复核容器：代码测试 → 构建检查 → HTTP 冒烟，完成后自行退出，
# 容器退出码即复核结果（0 成功，非 0 失败）：
docker compose up --build verify
```

- `web`：多阶段构建，`vite build` 产物由 nginx 提供；
  容器健康检查直接抓取首页并核对应用标记（静态应用可用才健康）。
- `verify`：等待 `web` 健康后运行 [scripts/verify.sh](scripts/verify.sh)——
  `npm test`、`npm run build`（并核对 Worker bundle 已产出）、
  对首页/JS/CSS/Worker 资源/`/healthz` 做 HTTP 冒烟，任一失败即以非零码退出。

## 内置样例

页面载入时默认填充“闭环矛盾三角形”：

| 边 | 目标差 | 权重 |
|---|---|---|
| 0→1 | 1 | 10 |
| 0→2 | 1 | 1 |
| 1→2 | 1 | 10 |

按录入顺序选生成树 `{0→1, 0→2}` 逐边累加得 `(0,1,1)`，高权闭合边 `1→2`
残差 −1，代价 10；精确最小割最优解为 `(0,1,2)`，只有低权弦残差 1，代价 **1**。
另提供一个四环“局部累加失败”样例（按钮载入）。

“复测闭环样例（单向绕行）”：可疑边 `0→3` 与 `3→1`，出发探针 1。
从 1 看 `3→1` 的尾最近（2 跳），最近边优先贪心先抢它会走
`1→2→3→1` 再 `1→2→3→0→3` 再 `3→1`，共 **8** 步；
最小费用平衡闭环顺单向洋流 `1→2→3→0→3→1` 仅 **5** 步。
